# 0002: ADR 与 Spec 一律采用中文编写

本项目中的所有架构决策记录（ADR）与功能规格说明文档（Spec）必须统一使用中文编写。

## 状态 (Status)

已采纳 (Accepted)

## 背景 (Context)

为了保证团队协作、架构沟通以及需求追溯过程中的高效与清晰，避免双语混杂造成的设计理解偏差，需要明确规定项目技术文档的主导语言。

## 决策 (Decision)

1. 所有架构决策记录文件（`docs/adr/*.md`）必须使用中文编写，遵循标准 ADR 结构（标题、状态、背景、决策、影响）。
2. 所有功能规格说明文件（`.scratch/<feature-slug>/spec.md`）必须使用中文编写，遵循标准 Spec 结构（问题陈述、解决方案、用户故事、实现决策、测试决策、不在范围内、进一步说明）。
3. 英文技术术语、库名、C-ABI 符号名等专业词汇保持原样，无需生硬意译。

## 影响 (Consequences)

- 保证了项目核心架构文档和需求规格的表达一致性与可读性。
- 后续无论由人类工程师还是 AI 代理生成或迭代 ADR/Spec，均须严格遵循此中文撰写规范。
